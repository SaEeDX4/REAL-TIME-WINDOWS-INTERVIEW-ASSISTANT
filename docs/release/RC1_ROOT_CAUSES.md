# 2.1.0-rc.1 — root-cause analysis (written before code changes)

| # | Symptom (manual E2E) | Root cause (traced in code) | Fix strategy |
|---|---|---|---|
| 1 | Two-part question with a ~0.5 s pause became two history entries / two answers | `TurnDetector` settles a text ending in `?` after only 450 ms measured from the *arrival* of the server-VAD `speech_stopped` event. That event already lags the real silence by the VAD silence window (400 ms), and the next part's `speech_started` arrives 200–400 ms after the interviewer resumes (VAD onset + audio buffering + network). For pauses ≥ ~0.5 s the deadline expired before the resumption was visible. Once finalized, nothing could re-join a continuation. | Two layers: (a) slightly longer, still adaptive settle for complete-sounding questions and longer for open continuations / announced multi-part questions; (b) a **continuation window** after finalization: if interviewer speech resumes within it (the candidate is expected to be speaking then), the new segment is merged into the previous turn, the provisional answer is cancelled and the SAME history entry is re-answered with the merged question. Pleasantries never reopen a turn; restarts ("sorry, let me rephrase…") replace the text. |
| 2 | "XAB utility" transcribed as "app utility" | (a) `MainViewModel.StartLeaseAsync` passes `targetId: null` to `CloudSession.StartAsync`; (b) even with an id, the backend builds the prompt from the user's **server** `target` document, but the desktop never uploads targets — the server always fell back to the generic "Job interview." prompt; (c) secret renewal on reconnect did not pass the interview language. | Desktop publishes a minimal *transcription context* document (job title, company, products, vocabulary, alias canonical terms — no résumé/JD text) for the active target before starting a lease and sends the target id. Backend resolves the document by `(id, userId)` only, builds a bounded prompt; renew uses the session's stored target. CloudSession remembers the language for renewals. |
| 3 | Typed question while paused → "AI unavailable (Unknown)" | Pause correctly ends the billable lease; `CloudAnswerProvider` still sent `purpose=live` with a null session id; the backend requires an active session for `live` → 403 `no_active_session`. | New server purpose **`manual`**: authenticated, entitlement-checked (paid access or remaining trial), device-checked when a device id is supplied, separate daily manual cap plus the existing per-minute rate limiter and daily/global answer caps; never touches live seconds. Client uses `live` only while a lease is active, otherwise `manual`, and falls back to `manual` once if the lease ended between check and request. |
| 4 | Known server errors shown as "Unknown" | `CloudAnswerProvider.Map` mapped only 401/429/400/0/5xx; 402/403/404/409 became `Unknown`, and the engine printed the enum name. The API error code was discarded. | `ProviderException` carries the server code; new kinds (`SessionEnded`, `QuotaExceeded`, `DeviceRevoked`, `AccountDisabled`, `Forbidden`, `NotSignedIn`, `ServiceUnavailable`); one mapping table to short actionable text; correlation id kept for diagnostics only. |
| 5 | Risk of fabricated history | `PromptBuilder` hard-coded one specific candidate's education and languages into **every** user's system prompt; `QuestionClassifier` decided "bridge vs verified" from a hard-coded topic list instead of the user's confirmed evidence; `FactValidator` treated generic words ("Engineering", "Product") as anchors that legitimise "I built…" claims, skipped claim checks entirely in VERIFIED mode and missed contractions ("I've built"). | Profile digest built only from the user's confirmed facts; direct-experience questions classified by evidence overlap with confirmed facts; every first-person past claim must overlap confirmed evidence or it is rewritten to "I'd …"; for direct-experience questions without evidence the engine guarantees an honest bridge as the first bullet. |
| 6 | Default answers sometimes needed scrolling | Default spec allowed "3 (4 if necessary)" bullets and the engine hard cap was 6. | Default = exactly 3 bullets, engine cap per style (3 default, 2 rapid, 4 technical). |
| 7 | Language combo boxes showed `LanguageInfo { Code = … }` / `LangItem { … }` | The custom `Combo` template's selection presenter bound `SelectionBoxItemTemplate` but not `ItemTemplateSelector`; `DisplayMemberPath` is implemented through the selector, so the closed box fell back to the record's `ToString()`. | Template binds `ContentTemplateSelector`/`ContentStringFormat`; display records override `ToString()` as a second line of defence. |
| 8 | "239 / 224 min left" | Lease `RemainingSeconds` = min(plan period, per-account daily cap, global cap) but was labelled as plan minutes. | API returns period and today's remaining separately; UI labels both. |
| 9 | "NO AUDIO" looked like an error during normal silence | Engine raised `NoAudio` after 20 s of silence with a warning colour. | Neutral "Listening · quiet" state; warning only after a longer threshold, once per silence period. |
